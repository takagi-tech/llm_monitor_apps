# みはる デプロイ手順書（Raspberry Pi）

各ネットワーク（AI2 / AI3）の Raspberry Pi に「みはる」を立てて、常時起動の稼働モニターにするための手順です。
**コピペで進められる形**にしてあります。`<...>` の部分は自分の環境の値に読み替えてください。

> 背景・ネットワーク構成・なぜこの手順なのかは [運用ガイド](運用ガイド.md) を参照。
> ここは「実際に手を動かす手順」に絞っています。

---

## 0. 前提（AI2 / AI3 共通）

- Raspberry Pi に **64bit OS（arm64）** が入っていること（`uname -m` が `aarch64`）。
- Pi に **Docker** と **Docker Compose** が入っていること。
  ```bash
  docker --version
  docker compose version
  ```
  入っていなければ（AI2のPiなど、ネットがある環境で）：
  ```bash
  curl -fsSL https://get.docker.com | sh
  sudo usermod -aG docker $USER   # 実行後は一度ログインし直す
  ```

---

## 1. AI2 のPi（インターネット接続可）

ネットに出られるので、Pi 上で直接クローン＆ビルドできます。

### 1-1. 取得と起動

```bash
git clone <リポジトリURL>
cd llm_monitor_apps
cp endpoints.json.example endpoints.json    # 初回のみ（空の登録ファイルを用意）
docker compose up --build -d
```

> `cp` を忘れると、compose のマウントで `endpoints.json` がディレクトリとして作られて壊れます。**必ず先に実行。**

### 1-2. 起動確認

```bash
docker compose ps          # State が Up になっているか
docker compose logs -f     # 起動ログ（Ctrl+C で抜ける）
```

ブラウザで `http://<PiのIP>:8000/` を開く（PiのIPは `hostname -I` で確認）。
「みはる」の画面が出ればOK。

### 1-3. マシンを登録する

起動直後は **登録0件** です。画面の「マシンの登録」から、**AI2のGPUマシンだけ**を1台ずつ登録します。

- `マシン名`：識別しやすい名前（例 `a6000-01`）
- `ネットワーク`：**AI2**
- `IPアドレス`：`192.168.86.x`
- `ポート`：LLMサーバーの待ち受けポート（例 `8000`）

登録後、20秒ごとに自動でオンライン状態とモデル名が更新されます。

## 2. AI3 のPi（閉域・インターネット非接続）

AI3はネットに出られないので、**Pi上で `git clone` も `docker compose --build` も失敗します**。
そこで「ネットのある環境でイメージを作り、ファイルにして物理的に持ち込む」方式（スニーカーネット）を取ります。

### 2-1. 【ネット可の環境で】イメージを作って書き出す

**AI2のPi**（＝同じ arm64）でやるのが確実です。

```bash
# AI2のPi（ネット可・arm64）で
cd llm_monitor_apps
docker compose build                                  # イメージをビルド
docker images | grep miharu                            # 生成されたイメージ名を確認
docker save <イメージ名>:latest -o miharu.tar          # tarに書き出す
```

> **CPUアーキテクチャを必ず一致させること。** Piは arm64。x86のPCで作ると Piで
> `exec format error` になり動きません。Apple SiliconのMacで作った場合は arm64 なのでOK。

### 2-2. 【物理的に運ぶ】USBでtarをAI3のPiへ

`miharu.tar` と、ソース一式（`docker-compose.yml` と `endpoints.json.example` が要る）を
USBメモリでAI3のPiにコピーします。

> ⚠️ USBは閉域にマルウェアが入る古典的経路です。**AI3専用のUSBを決め、他で使い回さない**こと。

### 2-3. 【AI3のPiで】読み込んで起動（--build しない）

```bash
cd llm_monitor_apps                     # 運んだソース一式の場所
docker load -i /path/to/miharu.tar      # イメージを取り込む
cp endpoints.json.example endpoints.json   # 初回のみ
docker compose up -d                    # ← --build は付けない
```

ブラウザで `http://<AI3のPiのIP>:8000/` を開く。

### 2-4. マシンを登録する

画面から、**AI3のGPUマシンだけ**を登録します（`ネットワーク`＝**AI3**、`IPアドレス`＝`10.0.1.x`）。

## 3. 更新（新しいバージョンを反映する）

### AI2（ネット可）

```bash
cd llm_monitor_apps
git pull
docker compose up --build -d
```

### AI3（閉域）

2-1〜2-3 をもう一度行います（新しいtarを作って持ち込み、`docker load` → `docker compose up -d`）。
`endpoints.json` はマウントされているので、更新しても登録内容は保持されます。

---

## 4. 日常の操作

```bash
docker compose ps         # 稼働確認
docker compose logs -f    # ログ確認
docker compose restart    # 再起動
docker compose down       # 停止
docker compose up -d      # 起動
```

- `restart: unless-stopped` を設定済みのため、**Pi再起動後も自動で立ち上がります**。
- 登録データ（`endpoints.json`）はホスト側に残り、コンテナを作り直しても保持されます。

## 5. 困ったとき

| 症状 | 原因・対処 |
|---|---|
| `exec format error` で起動しない | イメージのアーキ不一致。**arm64機（Pi）でビルドし直す**。 |
| 画面が開けない | `docker compose ps` で Up か確認 / PiのIPを `hostname -I` で再確認 / 8000番ポートの競合 |
| `endpoints.json` がディレクトリになった | `cp endpoints.json.example endpoints.json` を先にやらずに起動した。作られたディレクトリを消し、ファイルを用意して起動し直す。 |
| 全マシンが offline のまま | Piと対象マシンが**同じネットワーク**にいるか / IP:ポートが正しいか / 対象で `/v1/models` が応答するか（`curl http://<ip>:<port>/v1/models`）|
| AI2のPiでAI3のマシンが offline | 正常。**AI2からAI3へは到達できない**。各Piには自ネットのマシンだけ登録する。 |
